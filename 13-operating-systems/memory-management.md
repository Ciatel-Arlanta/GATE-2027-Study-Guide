> **Prerequisites:** [Computer organisation: memory hierarchy](../10-computer-organization/memory-hierarchy-and-cache.md) · **Leads to:** [Virtual memory](virtual-memory.md)
> **PYQ weightage:** Low · 4 Qs since 2015 (2 since 2021) · DA: 0 · Trend: steady · Most asked: Multilevel Paging, Best Fit, Memory Management · Note: the PYQ books file most paging and page-table-size questions under "Virtual Memory" (11 since 2015), so treat paging arithmetic here as High priority

## Quick glance

- **Exam focus:** Paging address translation, single-level and multilevel page table sizing, dynamic contiguous placement (First-fit, Best-fit, Worst-fit), and segmentation base/limit bound checks. Typically tested as NAT numericals and conceptual MSQs. Note: In GATE PYQ books, core paging and address translation questions are historically indexed under [Virtual memory](virtual-memory.md).
- **Logical address** is generated by CPU; **physical address** names a location in physical RAM asserted on the memory bus.
- **Address binding** occurs at **compile time** (absolute code), **load time** (relocatable code), or **execution time** (dynamic relocation via relocation/base register). Run-time binding is required for virtual memory and swapping.
- **Contiguous allocation:** Fixed partitions suffer from **internal fragmentation**; variable partitions suffer from **external fragmentation** (mitigated by compaction if dynamic relocation is supported).
- **Placement policies:** First-fit allocates the first adequate hole; Best-fit allocates the smallest adequate hole (leaves smallest leftovers); Worst-fit allocates the largest hole.
- **Paging** maps fixed-size logical **pages** to physical **frames**. It eliminates external fragmentation, but leaves internal fragmentation in the last page (average $P/2$ per process).
- **Address split:** Logical address size $2^m$, page size $P = 2^k$ bytes $\implies$ low $k$ bits are offset $d$, high $m - k$ bits are page number $p$. Offset $d$ is copied unchanged to the physical address.
- **Page table size:** $\text{PTS} = \frac{\text{LAS}}{\text{PS}} \times \text{PTE size} = 2^{m-k} \times e$ bytes.
- **Multilevel paging** pages the page table itself. Each level contains $\frac{\text{Page Size}}{\text{PTE Size}}$ entries, indexed by $\log_2(\text{Page Size}/\text{PTE Size})$ bits.
- **Segmentation** divides memory into variable-sized logical units (code, stack, heap). Logical address is $(s, d)$. Trap is raised if $d \ge \text{Limit}$; otherwise $\text{PA} = \text{Base} + d$. Suffers from external fragmentation.

## 1. Address binding and logical vs. physical addresses [PYQ: Low]

Program execution requires mapping source identifiers to physical RAM locations. Address binding occurs in three distinct phases:

1. **Compile-time binding:** Emits absolute code with fixed physical addresses. Changing starting location requires recompilation.
2. **Load-time binding:** Emits relocatable code with base-relative offsets ($0$). Addresses are bound to physical locations at load time. If the process moves in memory, it must be reloaded.
3. **Execution-time (run-time) binding:** Addresses are bound during instruction execution. Requires hardware support: the **Memory Management Unit (MMU)**. Allows dynamic swapping and relocation.

```text
CPU ---> Logical Address (LA) ----+
                                  |
                                  v
                      +-----------------------+
                      | Is LA < Limit?        | --- No ---> Trap: addressing error
                      +-----------------------+             (segmentation fault)
                                  | Yes
                                  v
                            [ + ] <--- Relocation Register (Base)
                              |
                              v
                       Physical Address (PA) ---> RAM
```

$$\text{PA} = \text{Base} + \text{LA} \quad \text{provided } 0 \le \text{LA} < \text{Limit}$$

**Worked example 1.1 (Dynamic relocation).** A CPU issues logical address $428_{10}$. The relocation register contains $12{,}500_{10}$, and the limit register contains $800_{10}$.
1. Validity check: $\text{LA} = 428 < \text{Limit} = 800$. The address is valid.
2. Translation: $\text{PA} = \text{Base} + \text{LA} = 12{,}500 + 428 = 12{,}928_{10}$.
3. If CPU generates $\text{LA} = 850_{10}$, the check $850 < 800$ fails $\implies$ hardware trap (addressing exception).

## 2. Contiguous allocation and fragmentation [PYQ: Medium]

In contiguous allocation, each process occupies a single contiguous memory block.

- **Fixed partitioning (MFT):** Memory is divided into static partitions. Causes **internal fragmentation** (allocated partition is larger than process demand).
- **Variable partitioning (MVT):** Partitions are carved dynamically to match process sizes. Causes **external fragmentation** (total free memory satisfies request, but free space is split into non-contiguous holes).
- **Compaction:** Relocates processes toward one end of memory to merge free holes into a single block. Only possible with **execution-time dynamic binding**.
- **50% Rule (Knuth):** For First-fit, if $N$ blocks are allocated, roughly $0.5 N$ blocks are lost to external fragmentation.

### 2.1 Placement strategies

- **First-fit:** Allocates the first hole with size $\ge S$. Fast; terminates early.
- **Best-fit:** Allocates the smallest hole with size $\ge S$. Leaves tiny, often unusable leftover holes.
- **Worst-fit:** Allocates the largest hole ($H_{\max} \ge S$). Leaves the largest remaining fragment.

**Worked example 2.1 (Placement strategy trace).** Holes in address order: $100, 500, 200, 300, 600\text{ KB}$. Requests: $212, 417, 112, 426\text{ KB}$.

| Policy | Allocations and Hole Updates | Outcome for $426\text{ KB}$ |
|---|---|---|
| **First-fit** | $212 \to 500$ (rem $288$); $417 \to 600$ (rem $183$); $112 \to 288$ (rem $176$) | **Fails** (max hole remaining is $300\text{ KB}$) |
| **Best-fit** | $212 \to 300$ (rem $88$); $417 \to 500$ (rem $83$); $112 \to 200$ (rem $88$) | **Succeeds** (allocated in $600\text{ KB}$, rem $174$) |
| **Worst-fit** | $212 \to 600$ (rem $388$); $417 \to 500$ (rem $83$); $112 \to 388$ (rem $276$) | **Fails** (max hole remaining is $300\text{ KB}$) |

## 3. Paging and single-level page tables [PYQ: High]

Paging divides physical memory into fixed-size **frames** and logical memory into same-size **pages**. It completely eliminates external fragmentation.

```text
Logical Address (m bits):
+-------------------------------+-----------------------+
|      Page Number: p           |     Page Offset: d    |
|       (m - k bits)            |        (k bits)       |
+-------------------------------+-----------------------+
                |                                  |
                v                                  | (copied directly)
         [ Page Table ]                            |
         |  p  | Frame f |                         |
         +-----+---------+                         |
               | Frame f                           |
               v                                   v
Physical Address:
+-------------------------------+-----------------------+
|      Frame Number: f          |     Frame Offset: d   |
|         (n - k bits)          |        (k bits)       |
+-------------------------------+-----------------------+
```

### 3.1 Page Table Entry (PTE) fields

A PTE stores: Frame number ($f$), Valid/Invalid bit ($1$=resident, $0$=page fault), Dirty bit ($1$=modified), Reference bit ($1$=accessed recently), and Protection bits (Read, Write, Execute).

### 3.2 Sizing formulas

$$\text{Pages} = \frac{\text{LAS}}{\text{PS}} = 2^{m-k}, \quad \text{Frames} = \frac{\text{PAS}}{\text{PS}} = 2^{n-k}, \quad \text{Frame bits } f = n - k$$

$$\text{PTS} = (\text{Number of pages}) \times (\text{PTE size in bytes}) = 2^{m-k} \times e$$

$$\text{Internal fragmentation}: \text{worst case } = P - 1\text{ bytes}, \quad \text{average } = P / 2\text{ bytes per process}$$

**Worked example 3.1 (Page table sizing).** A byte-addressable system has $32$-bit logical addresses, $1\text{ GiB}$ physical memory, and $4\text{ KiB}$ page size. Each PTE stores the frame number, $1$ valid bit, $1$ dirty bit, $1$ reference bit, and $2$ protection bits. Entries are byte-aligned.
1. Page size $= 4\text{ KiB} = 2^{12}\text{ B} \implies \text{Offset } d = 12\text{ bits}$.
2. Logical pages $= 2^{32} / 2^{12} = 2^{20} \implies p = 20\text{ bits}$.
3. Physical frames $= 1\text{ GiB} / 4\text{ KiB} = 2^{30} / 2^{12} = 2^{18} \implies f = 18\text{ bits}$.
4. Raw PTE size $= 18\text{ (frame)} + 1\text{ (valid)} + 1\text{ (dirty)} + 1\text{ (ref)} + 2\text{ (prot)} = 23\text{ bits}$.
5. Byte-aligned PTE size $= \lceil 23 / 8 \rceil = 3\text{ bytes}$.
6. Page Table Size $= 2^{20} \times 3\text{ bytes} = 3\text{ MiB}$ (or $4\text{ MiB}$ if padded to $4\text{ bytes}$).

## 4. Multilevel and inverted page tables [PYQ: High]

### 4.1 Hierarchical (multilevel) paging

To avoid allocating megabytes of contiguous frames for sparse page tables, the page table is itself paged. Each table at every level must fit within **one page frame**:

$$\text{PTEs per frame} = \frac{\text{Page Size}}{\text{PTE Size}} = 2^{k-e} \implies \text{Index bits per level} = k - e$$

$$\text{Number of levels } L = \left\lceil \frac{m - k}{k - e} \right\rceil$$

For 2-level paging, logical address is split into $(p_1, p_2, d)$:
- $p_1$: Index into Page Directory (points to frame containing inner table).
- $p_2$: Index into Inner Page Table (points to data frame).
- $d$: Offset within data frame.

Without a TLB, translation with an $L$-level page table requires **$L$ memory accesses** for page table lookups plus **$1$ access** for data, totalling **$L + 1$ memory accesses**.

**Worked example 4.1 (Multilevel design - GATE 2023 / 2025).** A system uses $48$-bit virtual addresses, byte-addressable memory, and $4\text{ KiB}$ pages. PTEs at all levels are $8\text{ bytes}$.
1. Offset bits $d = \log_2(4\text{ KiB}) = 12\text{ bits}$. Page number bits $= 48 - 12 = 36\text{ bits}$.
2. Entries per frame $= 4\text{ KiB} / 8\text{ B} = 2^{12} / 2^3 = 512 = 2^9 \implies 9\text{ bits}$ per level.
3. Levels required $= \lceil 36 / 9 \rceil = 4\text{ levels}$.
4. Address breakdown: $p_1\,(9\text{ b}) \mid p_2\,(9\text{ b}) \mid p_3\,(9\text{ b}) \mid p_4\,(9\text{ b}) \mid d\,(12\text{ b})$.

### 4.2 Inverted page tables

An **Inverted Page Table (IPT)** has exactly one entry per physical frame in RAM (entry contains $\langle \text{PID}, p, \text{flags} \rangle$). Size depends strictly on physical RAM size, independent of virtual address width. Requires a hash table and TLB to prevent slow linear searches.

## 5. Segmentation and segmented paging [PYQ: Low]

Segmentation models the programmer's view: code, data, stack, heap as variable-length blocks.
- Logical address: $\langle \text{Segment } s, \text{ Offset } d \rangle$.
- Segment Table holds $\langle \text{Base}, \text{Limit} \rangle$ for each segment.
- Hardware check: If $d \ge \text{Limit} \implies$ **Trap (segmentation fault)**. Otherwise, $\text{PA} = \text{Base} + d$.
- Suffers from external fragmentation; no internal fragmentation.

**Worked example 5.1 (Segment translation).** Given segment table: $S_0(\text{Base}=219, \text{Limit}=600)$, $S_1(\text{Base}=2300, \text{Limit}=14)$, $S_2(\text{Base}=90, \text{Limit}=100)$.
- $\langle 0, 430 \rangle$: $430 < 600 \implies \text{PA} = 219 + 430 = 649$. Valid.
- $\langle 1, 14 \rangle$: $14 \not< 14$ (valid offsets are $0 \dots 13$) $\implies$ **Trap: limit violation**.
- $\langle 2, 99 \rangle$: $99 < 100 \implies \text{PA} = 90 + 99 = 189$. Valid.

## Formulas and facts to memorise

| Item | Formula / Fact | When to use |
|---|---|---|
| **Address bit split** | $m = p + d$, where $d = \log_2(\text{Page Size})$ | Splitting logical address into page and offset |
| **Frame bit count** | $f = \log_2(\text{PAS} / \text{Page Size}) = n - d$ | Finding physical frame index width |
| **Page Table Size (1-level)** | $\text{PTS} = \frac{\text{LAS}}{\text{PS}} \times \text{PTE size} = 2^{m-d} \times e$ | Single-level page table memory consumption |
| **Entries per frame** | $N_{\text{pte}} = \frac{\text{Page Size}}{\text{PTE Size}} = 2^{k-e}$ | Calculating capacity of one frame in multilevel paging |
| **Multilevel index bits** | $\log_2(\text{PS} / \text{PTE}) = k - e$ | Bits consumed by each hierarchical level |
| **Multilevel level count** | $L = \lceil (m - k) / (k - e) \rceil$ | Determining number of tree levels |
| **Segment address check** | $0 \le d < \text{Limit} \implies \text{PA} = \text{Base} + d$ | Validating segment address bounds |
| **Average internal frag** | $\frac{1}{2} \times \text{Page Size}$ per process | Estimating paging overhead |
| **Inverted Page Table size** | $(\text{Total Frames}) \times \text{Entry Size}$ | Calculating IPT size independent of LAS |
| **Memory accesses (no TLB)** | Single-level: $2$; $L$-level: $L + 1$ accesses | Address translation penalty |

## GATE traps

- **Offset bits are invariant under paging:** Offset $d$ in the logical address is copied directly into physical address. It is **never** translated or altered.
- **Strict inequality in segmentation limit check:** Access is valid **only if** $d < \text{Limit}$. If $d = \text{Limit}$, hardware raises an immediate trap because offsets are $0$-indexed ($0 \dots \text{Limit} - 1$).
- **PTE size vs. Frame number bits:** Always add control bits (valid, dirty, reference, protection) to frame number bits before rounding to bytes.
- **Byte-addressable vs. Word-addressable:** If memory is word-addressable ($1\text{ word} = 4\text{ bytes}$), page size and address spaces must be converted to words before computing offset bits.
- **Outer page directory must fit in ONE frame:** In multilevel paging, the top-level table must fit into a single page frame unless explicitly stated otherwise.
- **Paging eliminates external, not internal, fragmentation:** Paging has zero external fragmentation, but incurs internal fragmentation on the last allocated page.

## Practice

**Q1. (NAT)** A system uses $36$-bit virtual addresses and $32$-bit physical addresses with $8\text{ KiB}$ pages. The page table entry size is $4\text{ bytes}$. If a single-level page table is used, calculate the total size of the page table in megabytes (MiB).

<details><summary>Answer</summary>

**Answer:** $32\text{ MiB}$

**Solution:**
1. Page size $= 8\text{ KiB} = 2^{13}\text{ bytes} \implies d = 13\text{ bits}$.
2. Number of pages $= \frac{2^{36}}{2^{13}} = 2^{23}$ pages.
3. Page Table Size $= 2^{23} \times 4\text{ bytes} = 2^{25}\text{ bytes} = 32\text{ MiB}$.
</details>

**Q2. (MCQ)** Consider four memory holes of sizes $150\text{ KB}$, $500\text{ KB}$, $200\text{ KB}$, and $350\text{ KB}$ in order. Processes requesting $180\text{ KB}$, $220\text{ KB}$, and $110\text{ KB}$ arrive in sequence. Which of the following statements is TRUE?
- (A) First-fit allocates $220\text{ KB}$ in the $350\text{ KB}$ hole.
- (B) Best-fit leaves a $120\text{ KB}$ fragment in the $500\text{ KB}$ hole.
- (C) Worst-fit leaves a $130\text{ KB}$ fragment in the $350\text{ KB}$ hole.
- (D) Best-fit fails to allocate the third process.

<details><summary>Answer</summary>

**Answer:** (C)

**Solution:**
- Worst-fit trace:
  - $180\text{ KB} \to$ allocated in largest hole $500\text{ KB}$ (leaves $320\text{ KB}$). Holes: `[150, 320, 200, 350]`.
  - $220\text{ KB} \to$ allocated in largest hole $350\text{ KB}$ (leaves $130\text{ KB}$). Holes: `[150, 320, 200, 130]`.
  - $110\text{ KB} \to$ allocated in largest hole $320\text{ KB}$ (leaves $210\text{ KB}$). Holes: `[150, 210, 200, 130]`.
  The original $350\text{ KB}$ hole now has a $130\text{ KB}$ fragment.
</details>

**Q3. (NAT)** In a 2-level paging system with $32$-bit virtual addresses, the page size is $4\text{ KiB}$. An entry in the page directory is $4\text{ bytes}$, and an entry in the inner page table is $4\text{ bytes}$. A process currently has allocated code and data spanning a contiguous range of $32\text{ MiB}$. How many page frames in total are occupied by the page directory and inner page tables for this process?

<details><summary>Answer</summary>

**Answer:** $9$

**Solution:**
1. Page size $= 4\text{ KiB} = 2^{12}\text{ bytes}$.
2. Entries per page table frame $= \frac{4\text{ KiB}}{4\text{ B}} = 1024 = 2^{10} \implies p_1 = 10, p_2 = 10, d = 12$.
3. Each inner page table maps $1024 \times 4\text{ KiB} = 4\text{ MiB}$ of virtual memory.
4. For $32\text{ MiB}$ contiguous address space: $\frac{32\text{ MiB}}{4\text{ MiB}} = 8\text{ inner page tables}$.
5. Outer page directory occupies $1$ frame.
6. Total frames occupied $= 1 + 8 = 9\text{ frames}$.
</details>

**Q4. (MSQ)** Which of the following statements regarding memory management schemes is/are TRUE?
- (A) Paging completely eliminates external fragmentation.
- (B) In variable-partition allocation, dynamic relocation hardware is mandatory to perform compaction.
- (C) In an inverted page table, the number of entries is proportional to the size of the logical address space.
- (D) An access violation trap is generated if the segment offset $d$ equals the limit register value.

<details><summary>Answer</summary>

**Answer:** (A), (B), (D)

**Solution:**
- (A) is TRUE: Any free frame can be assigned to any page; no external fragmentation occurs.
- (B) is TRUE: Compaction relocates code at runtime, requiring execution-time dynamic binding.
- (C) is FALSE: IPT has one entry per physical frame in RAM, proportional to physical memory size.
- (D) is TRUE: Valid offsets are $0 \dots \text{Limit} - 1$. If $d = \text{Limit}$, $d < \text{Limit}$ fails, triggering a trap.
</details>

**Q5. (NAT)** Consider a system with $40$-bit virtual addresses and $34$-bit physical addresses. The page size is $16\text{ KiB}$. If the system employs a $3$-level page table where each level's page table fits within a single frame, and the page table entry size at all levels is $e$ bytes (a power of $2$). What is the minimum value of $e$?

<details><summary>Answer</summary>

**Answer:** $4$

**Solution:**
1. Page size $= 16\text{ KiB} = 2^{14}\text{ bytes} \implies d = 14\text{ bits}$.
2. Physical address $= 34\text{ bits} \implies$ Frames $= 2^{34} / 2^{14} = 2^{20} \implies$ Frame number requires $20\text{ bits}$.
3. PTE must store at least the $20$-bit frame number, so $\text{PTE size in bits} \ge 20\text{ bits}$.
4. Smallest power of $2$ bytes holding $20$ bits is $4\text{ bytes}$ ($32\text{ bits}$).
5. Verify indexing: With $e = 4\text{ bytes} = 2^2\text{ B}$, entries per frame $= 2^{14} / 2^2 = 2^{12} \implies 12\text{ bits}$ per level.
   Three levels can index $3 \times 12 = 36\text{ bits} \ge (40 - 14 = 26\text{ bits})$. Both constraints are satisfied.
   Minimum power-of-$2$ PTE size is $4\text{ bytes}$.
</details>

**Q6. (NAT)** A segmented memory system has the segment table: $S_0(\text{Base}=1000, \text{Limit}=400)$, $S_1(\text{Base}=2500, \text{Limit}=200)$, $S_2(\text{Base}=4000, \text{Limit}=600)$. Compute the sum of the physical addresses generated for the two valid logical addresses among: $A_1 = \langle 0, 399 \rangle$, $A_2 = \langle 1, 200 \rangle$, $A_3 = \langle 2, 450 \rangle$.

<details><summary>Answer</summary>

**Answer:** $5849$

**Solution:**
1. $A_1 = \langle 0, 399 \rangle$: $399 < 400$ (Valid) $\implies \text{PA}_1 = 1000 + 399 = 1399$.
2. $A_2 = \langle 1, 200 \rangle$: $200 \not< 200$ (Invalid, trap).
3. $A_3 = \langle 2, 450 \rangle$: $450 < 600$ (Valid) $\implies \text{PA}_3 = 4000 + 450 = 4450$.
4. Sum $= 1399 + 4450 = 5849$.
</details>

**Q7. (MCQ)** Consider a paging system with a page size of $2\text{ KiB}$. A program starts at logical address $0$ and requires memory for an array of $2500$ integers ($4\text{ bytes}$ each). Assuming no other data is in the process, the internal fragmentation incurred by this program is:
- (A) $0\text{ bytes}$
- (B) $240\text{ bytes}$
- (C) $1808\text{ bytes}$
- (D) $2048\text{ bytes}$

<details><summary>Answer</summary>

**Answer:** (B)

**Solution:**
1. Program size $= 2500 \times 4\text{ bytes} = 10{,}000\text{ bytes}$.
2. Page size $= 2\text{ KiB} = 2048\text{ bytes}$.
3. Pages needed $= \lceil 10{,}000 / 2048 \rceil = 5\text{ pages}$.
4. Allocated memory $= 5 \times 2048 = 10{,}240\text{ bytes}$.
5. Internal fragmentation $= 10{,}240 - 10{,}000 = 240\text{ bytes}$.
</details>
