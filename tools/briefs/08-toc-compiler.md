# Brief: 11-theory-of-computation + 12-compiler-design

Verify automata/grammar claims by brute force where possible (e.g. enumerate strings up to length 6 with Python to check a DFA or regex), and verify FIRST/FOLLOW sets and parse tables carefully.

## 1) 11-theory-of-computation/ (CS; ~8 marks)
Plan topics: Regular expressions; Finite automata; Regular languages; Context-free grammars; Push-down automata; Context-free languages; Pumping lemma; Turing machines; Undecidability.
Files: README.md, regular-languages-and-finite-automata.md, context-free-languages-and-pda.md, pumping-lemma.md, turing-machines-and-undecidability.md, CHEATSHEET.md, CHECKPOINT.md.
Must cover:
- Alphabets, strings, languages, operations; regular expressions (identities, equivalence checks, describing languages in words); DFA, NFA, epsilon-NFA; subset construction worked fully; DFA minimisation (table-filling / partition refinement) worked fully; counting states of the minimal DFA for classic languages (divisibility by n, "n-th symbol from the end", substring/suffix/prefix conditions, length mod k); regex <-> FA conversions (state elimination; Thompson construction briefly); Mealy/Moore machines (brief); Myhill-Nerode intuition.
- Regular languages: closure properties table; decision properties (emptiness, finiteness, equivalence, membership); identifying regular vs non-regular quickly (finite memory intuition; a^n b^n is not regular, a^n b^m is).
- CFGs: derivations, parse trees, ambiguity (with an inherently-ambiguous example), simplification, CNF (derivation length 2n - 1) and GNF; PDAs (acceptance by final state vs empty stack; DPDA vs NPDA; DCFLs, and that DCFL ⊂ CFL); CFG <-> PDA equivalence (idea); CYK (brief); closure properties of CFLs and DCFLs (union, intersection with regular, complement, etc.); decision properties.
- Pumping lemma for regular languages and for CFLs: exact statements, the adversarial-game proof template, fully worked non-regularity and non-context-freeness proofs (a^n b^n, ww, a^n b^n c^n, a^(n^2), primes), and why the pumping lemma cannot prove a language regular.
- Turing machines: definition, configurations, variants (multi-tape, non-deterministic — all equivalent), TM for a^n b^n c^n idea; recursive (decidable) vs recursively enumerable; Chomsky hierarchy table (grammar, automaton, closure); Church-Turing thesis; the universal TM; the halting problem (diagonal proof); reductions; Rice's theorem (how to apply it and when it does not apply); decidability table for regular/DCFL/CFL/CSL/REC/RE problems (membership, emptiness, finiteness, equivalence, ambiguity...); closure of REC and RE (complement: L and its complement both RE ⇒ REC); classic undecidable problems (PCP, CFG ambiguity, CFG equivalence, TM emptiness); a decision procedure for GATE "which of these languages is regular / CFL / REC / RE / not RE" questions.

## 2) 12-compiler-design/ (CS; ~5-6 marks)
Plan topics: Lexical analysis; Parsing; Syntax-directed translation; Runtime environments; Intermediate code generation; Local optimization; Data-flow analysis; Constant propagation; Liveness analysis; Common subexpression elimination.
Files: README.md, lexical-analysis.md, parsing.md, syntax-directed-translation.md, runtime-environments.md, intermediate-code-generation.md, optimization-and-dataflow.md, CHEATSHEET.md, CHECKPOINT.md.
Must cover:
- Compiler phases diagram (mermaid) and what each produces; symbol table; error handling per phase.
- Lexical analysis: tokens, lexemes, patterns; regex -> NFA -> DFA for lexers (link TOC); longest match and priority rules; counting tokens in a C snippet (a GATE favourite — several worked examples incl. comments, strings, operators like `>>=`); lexical errors.
- Parsing: CFG recap; left recursion removal and left factoring; FIRST and FOLLOW computation (worked step by step); LL(1) table construction and the LL(1) conditions; recursive descent; shift-reduce parsing; LR(0) items and the canonical collection (draw the DFA of item sets); SLR(1), CLR(1)/LR(1), LALR(1) table construction; shift-reduce and reduce-reduce conflicts; the parser hierarchy (LL(1) ⊂ LALR(1) ⊂ LR(1); SLR ⊂ LALR) and state-count relations (LR(0) = SLR = LALR ≤ CLR); operator-precedence parsing; handles and viable prefixes; YACC conflict resolution.
- SDT: synthesised vs inherited attributes, S-attributed vs L-attributed SDDs, annotated parse trees, evaluating an SDT for a given input (GATE gives a grammar with semantic actions and asks for printed output — work several such examples), translation schemes with embedded actions, building syntax trees/DAGs.
- Runtime environments: storage organisation (code, static, stack, heap), activation records (fields), calling sequences, static vs dynamic scoping and access links/displays, parameter passing (value, reference, value-result, name), heap management and garbage collection (brief).
- Intermediate code: three-address code, quadruples/triples/indirect triples, syntax trees and DAGs (counting nodes in a DAG for an expression), SSA (counting variables after conversion), translating expressions, boolean expressions with short-circuit, control flow (backpatching briefly), arrays; basic blocks (leaders algorithm) and control-flow graphs (counting basic blocks/edges).
- Optimisation: local optimisations (constant folding, constant propagation, copy propagation, CSE, dead-code elimination, strength reduction, algebraic simplification, peephole), DAG-based local CSE, loop optimisations (code motion, induction variables, loop unrolling); data-flow analysis framework (gen/kill, in/out equations, direction, meet operator) for reaching definitions, live variables (backward, union — compute live sets for a CFG fully), available expressions (forward, intersection), constant propagation lattice; register allocation via liveness and interference-graph colouring (min registers needed — a GATE favourite; link to graph colouring in discrete maths).
